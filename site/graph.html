Every edge came out of a connector

Nothing in this graph was hand emitted. Three DataHub connectors read Postgres, the dbt manifest and the MLflow registry, and the chain from a raw census column to a serving model joins up on its own. That was the bet the whole project was built on, because a graph you wrote yourself proves nothing about whether the approach works.

  • connectors postgres, dbt, mlflow
  • deepest column walk 7 hops
  • tagged columns 14 on dim_person
  • regimes 3 over one warehouse

The tag exists at dim_person and not at the feature table. That gap is the entire problem: the model reads a column that carries no governance metadata, one hop from a column that does.

the trap under everything

A table exists three times, and only one copy has the tags

dbt, Postgres and MLflow each hold their own entity for the same table, joined as siblings. Governance tags declared in dbt land on the dbt entity. Lineage traversal returns Postgres urns. So the obvious question, asked the obvious way, returns nothing.

entityholdstagged columns on dim_person
dbtthe manifest, descriptions, governance tags, the source file path14
postgresthe physical table, what traversal returns0
mlflowthe training frame as the model saw it0

Every check resolves siblings and reads the union before it answers. This is the most likely way to ship a governance check that looks like it works and does not.

ingestion

The order of the connectors changes what the graph contains

Two silent failures pulling in opposite directions, both found by experiment rather than by reading anything.

  • postgres must run after mlflow The mlflow connector overwrites the postgres entity's schema with the training frame's columns. Run in the obvious order it left the catalog claiming 13 columns on a table that had 15.
  • postgres must also run before dbt The dbt source resolves select * against the schema DataHub already holds for that platform, not against its own catalog. With postgres last, the new column got no edge at all while the other nine traced perfectly. 
datahub ingest -c ingest/postgres.yml   # so dbt can resolve select *
datahub ingest -c ingest/dbt.yml        # column level edges and tags
datahub ingest -c ingest/mlflow.yml     # runs, models, registry stages
datahub ingest -c ingest/postgres.yml   # again, to undo the schema overwrite

One column tracing and nine not is a bug you find. Nine tracing and one not is a bug you ship.

policy packs

One warehouse, three regimes, three different verdicts

Which columns are restricted is declared in YAML, not written into the checks. The same graph and the same tags produce different findings depending only on which pack is named, which is what makes the tool portable to a warehouse governed by a statute nobody here has read.

regimewatchesverdict on public_coverage_flag
employment_uscolumns tagged protected_attributenothing to report
ecoaprotected bases under fair lendingnothing to report
eu_ai_actprotected attributes and personal dataexamine, Article 10(2)(f)

Insurance coverage is genuinely not a protected characteristic in US employment law, so the first two are correct to stay quiet. The EU AI Act asks for examination of bias affecting fundamental rights rather than listing forbidden columns, so it catches it. Neither check is wrong, and the difference is a line of YAML.

without any tags

What if nobody labelled the warehouse

Everything above leans on somebody having tagged the columns, which is the weakest assumption in the whole design. The columns nobody thought about are exactly the ones that cause trouble. So the question runs the other way too: given a table and no tags at all, which columns hold a human attribute? 

python tools/identify.py public.raw_person

  9 identified, 3 ambiguous, 12 with nothing to say

Three rungs, cheapest first: the name, then the value distribution, then fitting a model. The coverage flag is honestly ambiguous at the cheap rungs, because it is coded one and two exactly like sex and disability, so it is handed up to the expensive rung rather than guessed at. That expensive rung is the one that found it in the first place.
